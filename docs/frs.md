# Functional Requirements Specification (FRS)
**Project:** Opportunity Radar V2 - Student Career Operating System
**Document Version:** 1.0

---

## Section 1: Feature Requirements

1.  **Resume Upload**
    *   System must allow authenticated students to upload their resume in PDF format.
    *   System must enforce a maximum file size of 5MB.
    *   System must store the original PDF securely in a cloud storage bucket.
2.  **Resume Parser**
    *   System must automatically extract text from the uploaded PDF.
    *   System must parse the extracted text into a structured JSON format containing: Skills, Education, Experience, and Projects.
    *   System must save the parsed JSON structure to the student's database profile.
3.  **ATS Engine**
    *   System must analyze a target Job Description against the student's parsed resume JSON.
    *   System must identify missing mandatory skills/keywords from the student's resume.
    *   System must visually highlight these gaps in the UI.
4.  **Match Score**
    *   System must calculate a percentage score (0-100%) indicating how well the student's resume matches the job description.
    *   System must use this Match Score to sort and filter the main Opportunity Feed.
5.  **Resume Optimizer**
    *   System must allow users to select a specific bullet point from their parsed experience.
    *   System must use generative AI to rewrite the selected bullet point using the STAR (Situation, Task, Action, Result) method.
    *   System must seamlessly integrate the missing keywords identified by the ATS Engine into the rewritten bullet point.
6.  **Tracker**
    *   System must provide a Kanban-style board with default columns: Saved, Applied, Interviewing, Offer, Rejected.
    *   System must allow students to move opportunity cards between columns via drag-and-drop.
    *   System must automatically add an opportunity to the "Applied" column when the student clicks "Apply" via the ATS Engine UI.

---

## Section 2: User Stories

1.  **As a student**, I want to upload my PDF resume so that I don't have to manually type out my work history and skills.
2.  **As a student**, I want to see a Match Score on every job posting so that I can quickly identify roles I am highly qualified for.
3.  **As a student**, I want to see exactly which keywords my resume is missing compared to a job description so that I can bypass automated ATS filters.
4.  **As a student**, I want the AI to suggest professional rewrites for my weak bullet points so that I sound more impactful without needing to be a great writer.
5.  **As a student**, I want a visual Kanban board of all my applications so that I never lose track of a deadline or forget to follow up.

---

## Section 3: Database Requirements

**New Tables Required:**
*   `resumes`: Stores uploaded resumes.
    *   `id` (uuid, pk), `user_id` (uuid, fk), `file_path` (text), `parsed_data` (jsonb), `is_active` (boolean), `created_at` (timestamp).

**Existing Tables to Modify:**
*   `opportunities`:
    *   Add `extracted_skills` (text[]) to store an array of required keywords parsed from the job description (used by the ATS Engine).
    *   Add `embedding` (vector) for future semantic search.
*   `profiles`:
    *   Add `primary_resume_id` (uuid, fk to `resumes.id`).
*   `application_tracker`:
    *   Add `ats_match_score_at_apply` (integer) to track historical match rates.

---

## Section 4: API Requirements

*   `POST /api/resume/parse`: Accepts a PDF file, uploads to storage, calls LLM for JSON extraction, and updates the database.
*   `GET /api/ats/analyze`: Accepts `opportunity_id` and `resume_id`. Returns the Match Score integer and an array of `missing_keywords`.
*   `POST /api/resume/optimize`: Accepts `original_bullet` (string) and `target_keywords` (string[]). Returns 3 rewritten bullet options generated by AI.
*   *Note: Application Tracker and Match Score feed ranking will be handled directly via Supabase PostgREST and Next.js Server Actions.*

---

## Section 5: AI Requirements

1.  **Parsing Engine:**
    *   **Model:** Gemini 1.5 Flash.
    *   **Input:** Raw text extracted from PDF.
    *   **Prompt:** "Extract the following text into a strict JSON schema: { skills: string[], experience: [{ role, company, bullets: string[] }], education: [...] }."
    *   **Output:** Validated JSON.
2.  **Optimizer Engine:**
    *   **Model:** Gemini 1.5 Flash.
    *   **Input:** User's bullet point + Missing Job Keywords.
    *   **Prompt:** "Rewrite this resume bullet using the STAR method. It must sound professional and naturally include the following keywords: [Keywords]."
    *   **Output:** 3 string variations.
3.  **Cost Mitigation:** Both engines must utilize fast, low-cost models (Flash). Complex reasoning models (Pro) are unnecessary for these specific extraction/formatting tasks.

---

## Section 6: UI Requirements

1.  **Resume Upload Modal:** Drag-and-drop zone with a loading state indicating parsing progress.
2.  **Opportunity Radar Feed:** Standard feed updated to include a prominent circular badge displaying the Match Score (Green > 80%, Yellow 50-79%, Red < 50%).
3.  **ATS Center (Split Screen):**
    *   *Left Panel:* Target Job Description text.
    *   *Right Panel:* Student's Parsed Resume Data.
    *   *Header:* Match Score Gauge and a list of red "Missing Keywords".
4.  **Bullet Optimizer Dialog:** A modal appearing over the ATS Center. Shows the original bullet and provides three AI-generated alternatives. Includes a "Replace" button.
5.  **Tracker Board:** A full-width Kanban board. Cards must display the Company Logo, Job Title, and Time Since Applied.

---

## Section 7: Acceptance Criteria

1.  **Resume Parser:** A standard 1-page PDF must be parsed and saved to the database within 15 seconds. The resulting JSON must contain at least 80% of the skills listed in the PDF.
2.  **ATS Engine:** The system must accurately flag a required keyword (e.g., "Python") as missing if it exists in the job description but not in the parsed resume.
3.  **Match Score:** Must return a valid integer between 0 and 100 instantly upon page load for any job.
4.  **Resume Optimizer:** Must generate 3 grammatically correct bullet points that explicitly contain the requested missing keywords.
5.  **Tracker:** Moving a card from "Saved" to "Applied" must persist in the database and not reset upon page refresh.

---

## Section 8: Out of Scope

The following features have been intentionally excluded from this specification to prevent feature bloat and ensure delivery:
*   Real-time Voice Interview Simulator.
*   Text-based Mock Chat Simulator.
*   Chrome Extension Job Clipper.
*   Placement Readiness Score.
*   University/Dean's Analytics Dashboard (Postponed to later V2 phase).
*   Career Roadmapping.
