## 1. Executive summary

| | |
|---|---|
| **Overall build quality** | **7.0 / 10** — genuinely well-engineered core, undermined by deployment drift |
| **Overall completeness vs your plan** | **~58%** |
| **Production-ready today?** | **No.** Four blockers, all fixable in under a day. |

The single most important finding: **the code is in much better shape than the deployed database.** Seven tables the application queries do not exist in production, and three more exist but the service role cannot read them. Almost every "broken feature" traces back to that one gap, not to bad code.

The ingestion pipeline — the hardest part of this product — is working well: 98.7% of the 4,175 listings were re-verified within the last 24 hours. That is a real achievement and it is the thing most student-job products get wrong.

## 4. Security

**Rating: 7.5/10.** No exploitable vulnerability found. The previously-reported holes are genuinely closed.

### Verified good

- **Cron auth fails closed.** `lib/cron-auth.ts` returns 503 when `CRON_SECRET` is unset instead of comparing against the string `"Bearer undefined"`, and uses `timingSafeEqual`.
- **PostgREST filter injection is handled.** `sanitizeFilterTerm()` strips `, ( ) . " ' \ *` before interpolation into `.or()`. Lossy by design, correctly so.
- **IDOR-resistant tracker writes** — explicit `user_id` predicate on every mutation.
- **Auth is required unconditionally** on `/api/resume/parse` and `/api/resume/ats-check`. The old "skip auth when `NODE_ENV !== 'production'`" bypass is gone.
- **Security headers** all present: HSTS with preload, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, and a `Permissions-Policy` that keeps `microphone=(self)` for the future voice feature while disabling camera and geolocation.
- **Open-redirect protection** in both the live login component and `/auth/callback`.

### Issues

| Sev | Issue | Detail |
|---|---|---|
| **HIGH** | **AI rate limiting covers 4 of 17 features.** `RATE_LIMITS` defines only `resume_parser`, `resume_ats`, `resume_optimizer`, `skill_extraction`. `checkRateLimit` does `if (!limit) return true` — so `jd_intelligence`, `evidence_evaluation`, `resume_ats_v2_*`, `hr_coaching`, `assistant`, `schema_repair` and both new optimisation features are **completely unlimited**. An authenticated user can drain your provider quota. |

## 5. Licensing — needs your decision

`features/resume/` and 198 other files import from `@reactive-resume/*`, resolved by `tsconfig.json` paths to a vendored copy in `frontend/packages/`.

The local fork at `/Users/laxmansirvi/reactive-resume/` is labelled:

```
name: "resumeai",  license: "MIT",  author: "ResumeAI"
remote: https://github.com/Laxmansirvi05/ResumeAI.git
```

Upstream **Reactive Resume is AGPL-3.0** from v4 onward. If the vendored code descends from an AGPL version, relabelling it MIT does not change its licence, and AGPL-3.0 requires you to offer source to every user of a network-deployed service.

**Not a code defect — a legal one.** Confirm which upstream version and licence the fork was taken from before any public deployment. If it is AGPL, either publish your source or replace the builder.
